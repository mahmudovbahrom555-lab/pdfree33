Frequently Asked Questions

What is PDF/A?

PDF/A is an ISO-standardized (ISO 19005) version of PDF designed for long-term archiving. It requires all fonts to be embedded, forbids encryption and embedded JavaScript, and embeds color-profile and metadata information so the document renders identically decades from now, independent of external resources.

What's the difference between PDF/A-2b and PDF/A-2u?

PDF/A-2u adds one requirement on top of 2b: every font must have a verified Unicode mapping, so your document's text stays properly searchable and copy-pasteable, not just visually correct. PDFree checks this automatically and targets 2u whenever your fonts qualify, falling back to 2b otherwise — you don't have to choose.

Why does my PDF fail the compliance check?

The most common reason is unembedded fonts — many PDFs reference standard fonts like Helvetica or Arial by name instead of embedding them, which PDF/A does not allow. Other reasons include a password/encryption, an already-applied digital signature, embedded JavaScript or automatic open actions (including ones hidden inside a single link or form field), and old LZW-compressed image streams.

Can PDFree fix a PDF with missing fonts?

Sometimes, as an explicit opt-in. If the missing fonts are Helvetica/Arial, Times, or Courier, PDFree can offer a free, metrically-compatible substitute (the Liberation font family) — but only after verifying your document's exact character widths match, so text can't silently shift. If verification fails for even one font, nothing is changed and conversion stays refused. For anything else, PDFree tells you exactly which fonts aren't embedded so you can re-export the source document with fonts embedded instead.

Does converting remove JavaScript or interactive features from my PDF?

Yes, when present — PDF/A forbids embedded JavaScript and automatic actions, including form-field calculation scripts (e.g. an auto-summed total field). PDFree removes these automatically as part of conversion and tells you exactly what was removed, so you're never surprised that a form stopped auto-calculating after archiving.

Does PDFree preserve an existing digital signature?

PDFree checks for one first. Any modification to a signed PDF — including this conversion — invalidates its existing signature, so if PDFree detects one already applied, it refuses to convert and tells you to sign the archived copy afterward instead, rather than silently producing a file with a broken signature.

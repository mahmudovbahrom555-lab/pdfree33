2. Главный принцип и рамки v1

6. Когда остаётся оригинал

  1. До обработки изображения: всё, что вне рамок раздела 2 (неизвестный /Decode, маркер JPEG, не 8 бит, SMask), — пропускается без попытки.
  2. После перекодирования, в браузере: новое изображение декодируется и сравнивается с исходным — V1 (чистый K) и средний ΔCMYK. Нарушение — сохраняются исходные байты этого изображения.
  3. Любая ошибка декодирования или кодирования — исходное изображение; файл продолжает обрабатываться остальными шагами.
  4. Файл не меньше исходного — возвращается исходный файл (правило C, уже на проде).

7. Как проверяется сама проверка

Прежде чем доверять гейту, он проверяется в обе стороны (правило проекта):

  • одинаковые сборки → 0 FAIL;
  • намеренно сломанные сборки → FAIL обязательно: CMYK → RGB; добавить 3% C/M/Y в чистый K; заменить ICC-профиль; снять OP в ExtGState; уменьшить JPEG до качества 30.

Инструменты: PyMuPDF и qpdf (есть), littleCMS через Pillow (есть, 2.17), Poppler (есть), Ghostscript (поставить: brew локально, apt в CI). Скрипты — в scripts/compress-cmyk/, пороги — в одном файле, который меняется только отдельным коммитом с записью причины.

8. Решения, которые нужны до кода

Решение 1

Standard — только без потерь (L)? Maximum — L + уменьшение разрешения (D)?

От этого зависят ожидания по размеру: L даёт мало, основной выигрыш — D.

Решение 2

Пороги V2–V5

Утвердить после калибровки (раздел 5), не раньше.

Решение 3

Эталонный CMYK-профиль, когда в файле нет OutputIntent

Варианты: Coated FOGRA39 (Европа), GRACoL/SWOP (США), или проверять по тому профилю, которым рисует MuPDF. Влияет только на измерение, не на файл.

Решение 4

Порог DPI для D

Предложение: Maximum — 200 dpi для фото; меньше никогда для изображений с чистым K (текст в картинке).

9. Порядок работы после утверждения

  1. Синтетические фикстуры и скрипты гейта; проверка гейта в обе стороны (раздел 7).
  2. Калибровка порогов и их утверждение владельцем.
  3. Режим L — реализация, прогон: разработка → контроль → весь корпус.
  4. Режим D — отдельно, с той же процедурой.
  5. Ручное сравнение владельцем с A на 2–5 документах; B, C, D — не ориентиры (переводят в RGB или портят цвет).
  6. PR → одобрение → прод → проверка на pdfree.io.

Pourquoi les Outils PDF Sans Envoi Sont Différents

La plupart des outils PDF en ligne fonctionnent de la même façon : vous envoyez votre fichier sur leur serveur, leur serveur le traite, et vous téléchargez le résultat. Cela signifie que votre document — qui contient peut-être des contrats, des dossiers médicaux, des données financières ou des informations personnelles — voyage sur internet et réside temporairement sur l'infrastructure d'un tiers.

PDFree est conçu différemment. Le moteur de traitement PDF s'exécute dans votre navigateur via WebAssembly. Lorsque vous déposez un fichier dans PDFree, le navigateur le lit directement depuis votre disque. Aucun octet de votre document n'est transmis nulle part. Le résultat est généré en mémoire et téléchargé directement sur votre appareil.

Comment fonctionne le traitement côté navigateur : Votre PDF est lu par la File API du navigateur (accès local au disque uniquement). Les modules WebAssembly (pdf-lib, PDF.js) traitent le fichier entièrement en mémoire. Le résultat est écrit dans une URL Blob puis téléchargé — il ne touche jamais un socket réseau.

Comment Ça Marche — WebAssembly + pdf-lib + PDF.js

PDFree utilise trois technologies pour traiter les PDF sans aucun serveur :

WebAssembly (Wasm)

WebAssembly est un format d'instructions binaire qui s'exécute dans tous les navigateurs modernes à une vitesse quasi native. PDFree utilise Wasm pour exécuter du code de manipulation PDF directement dans votre navigateur — le même code qui tournerait autrement sur un serveur s'exécute désormais sur votre machine.

pdf-lib (Modification)

pdf-lib est une bibliothèque JavaScript pour créer et modifier des documents PDF. PDFree l'utilise pour des opérations comme la fusion, la division, la rotation, le filigrane et l'ajout de numéros de page. Toute la manipulation se fait en mémoire du navigateur.

PDF.js (Rendu)

PDF.js est le moteur de lecture et de rendu PDF de Mozilla, également écrit entièrement en JavaScript. PDFree l'utilise pour les opérations nécessitant le rendu de pages — comme la conversion de pages PDF en images JPG. Il s'exécute entièrement côté client.

Service Worker (Hors Ligne)

Un Service Worker met en cache tous les scripts, modules WebAssembly et polices lors de votre première visite. Lors des visites suivantes — même sans aucune connexion internet — les outils se chargent depuis le cache et traitent les PDF entièrement hors ligne. C'est la même technologie utilisée par les Progressive Web Apps (PWA) façon application native.

Confidentialité : Pas de Serveur = Pas de Risque

Lorsqu'un outil traite votre PDF sur un serveur, plusieurs choses se produisent : votre fichier est transmis sur internet (chiffré, mais tout de même), arrive sur leur infrastructure, est écrit sur disque ou en mémoire, et leur code le manipule. Même si un fournisseur supprime les fichiers après traitement, il existe une fenêtre d'exposition.

PDFree élimine totalement ce risque. Comme aucun serveur n'est impliqué :

  • Aucun risque RGPD — aucune donnée personnelle n'est envoyée à un responsable de traitement hors de votre appareil
  • Aucune rétention de données — il n'y a rien à conserver ; les fichiers n'existent que dans la mémoire de votre navigateur pendant le traitement
  • Aucun risque de fuite — un serveur peut être compromis ; la mémoire de votre navigateur ne peut pas être atteinte à distance
  • Sûr pour les documents confidentiels — contrats, dossiers médicaux, documents financiers et pièces juridiques peuvent tous être traités en toute sécurité
  • Fonctionne sur des réseaux isolés — aucune connexion sortante n'est établie pendant le traitement du PDF

Questions Fréquentes

Puis-je utiliser ces outils PDF sans connexion internet ?

Oui. Après votre première visite, PDFree fonctionne entièrement hors ligne. Un Service Worker met en cache toute l'application — scripts, modules WebAssembly et polices. Lors de toute visite ultérieure, même sans internet, tous les outils se chargent depuis le cache et traitent les PDF sans avoir besoin de connexion réseau.

Mon PDF est-il vraiment envoyé quand j'utilise PDFree ?

Non. Votre PDF est lu depuis votre disque local par la File API du navigateur et traité en mémoire du navigateur. Aucun octet de votre fichier n'est envoyé via une connexion réseau. Vous pouvez le vérifier vous-même : ouvrez les DevTools de votre navigateur → onglet Réseau et observez qu'aucune requête d'envoi de fichier n'apparaît — il n'y en a aucune.

En quoi est-ce différent des outils PDF dans le cloud ?

Les outils cloud envoient votre fichier sur leurs serveurs, le traitent à distance, puis vous renvoient le résultat. Votre document se trouve temporairement sur leur infrastructure. PDFree fait l'inverse — le moteur de traitement vit dans votre navigateur. Votre fichier ne quitte jamais votre appareil. Cela rend PDFree fondamentalement plus sûr pour les documents sensibles et utilisable sans internet après le premier chargement.

PDFree fonctionne-t-il sur mobile sans envoi de fichiers ?

Oui. PDFree fonctionne sur Safari iOS, Chrome Android et tous les navigateurs mobiles modernes. Le traitement basé sur WebAssembly fonctionne de la même façon sur mobile — sans envoi, sans serveur. Vous pouvez aussi installer PDFree comme PWA depuis le menu de votre navigateur pour un accès hors ligne rapide depuis votre écran d'accueil.

Est-ce vraiment gratuit, sans piège caché ?

Oui. PDFree n'a aucun forfait payant, aucune limite quotidienne, aucun plafond de taille de fichier, aucun filigrane sur le résultat et aucun compte requis. Tous les outils sont gratuits pour toujours. Le projet est open source sous licence GNU AGPLv3 — vous pouvez inspecter le code source pour vérifier exactement comment il fonctionne.

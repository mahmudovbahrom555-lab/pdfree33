Warum PDF-Tools ohne Upload anders sind

Die meisten PDF-Tools im Internet funktionieren alle gleich: Du lädst deine Datei auf deren Server hoch, der Server verarbeitet sie, und du lädst das Ergebnis herunter. Das bedeutet, dass dein Dokument — das möglicherweise Verträge, medizinische Unterlagen, Finanzdaten oder persönliche Informationen enthält — durchs Internet reist und vorübergehend auf der Infrastruktur eines Fremden liegt.

PDFree ist anders aufgebaut. Die PDF-Verarbeitungs-Engine läuft in deinem Browser per WebAssembly. Wenn du eine Datei in PDFree ablegst, liest der Browser sie direkt von deiner Festplatte. Kein Byte deines Dokuments wird irgendwohin übertragen. Die Ausgabe wird im Arbeitsspeicher erzeugt und direkt auf dein Gerät heruntergeladen.

So funktioniert clientseitige Verarbeitung: Deine PDF wird über die File API des Browsers gelesen (nur lokaler Festplattenzugriff). WebAssembly-Module (pdf-lib, PDF.js) verarbeiten die Datei vollständig im Arbeitsspeicher. Das Ergebnis wird in eine Blob-URL geschrieben und heruntergeladen — es berührt nie einen Netzwerk-Socket.

So funktioniert es — WebAssembly + pdf-lib + PDF.js

PDFree nutzt drei Technologien, um PDFs ganz ohne Server zu verarbeiten:

WebAssembly (Wasm)

WebAssembly ist ein binäres Befehlsformat, das in allen modernen Browsern nahezu nativ schnell läuft. PDFree nutzt Wasm, um PDF-Verarbeitungscode direkt in deinem Browser auszuführen — derselbe Code, der sonst auf einem Server laufen würde, läuft jetzt auf deinem Gerät.

pdf-lib (Bearbeitung)

pdf-lib ist eine JavaScript-Bibliothek zum Erstellen und Bearbeiten von PDF-Dokumenten. PDFree nutzt sie für Vorgänge wie Zusammenführen, Aufteilen, Drehen, Wasserzeichen und Seitenzahlen. Die gesamte Bearbeitung erfolgt im Arbeitsspeicher des Browsers.

PDF.js (Rendering)

PDF.js ist Mozillas PDF-Lese- und Rendering-Engine, ebenfalls vollständig in JavaScript geschrieben. PDFree nutzt sie für Vorgänge, die das Rendern von Seiten erfordern — etwa das Umwandeln von PDF-Seiten in JPG-Bilder. Sie läuft komplett clientseitig.

Service Worker (Offline)

Ein Service Worker speichert bei deinem ersten Besuch alle Skripte, WebAssembly-Module und Schriftarten zwischen. Bei späteren Besuchen — selbst ganz ohne Internetverbindung — laden die Tools aus dem Cache und verarbeiten PDFs vollständig offline. Das ist dieselbe Technologie, die native-app-ähnliche Progressive Web Apps (PWAs) nutzen.

Datenschutz: Kein Server = kein Datenrisiko

Wenn ein Tool deine PDF auf einem Server verarbeitet, passiert Folgendes: Deine Datei wird übers Internet übertragen (verschlüsselt, aber trotzdem), landet auf fremder Infrastruktur, wird auf Festplatte oder in den Arbeitsspeicher geschrieben, und fremder Code verarbeitet sie. Selbst wenn ein Anbieter Dateien nach der Verarbeitung löscht, gibt es ein Zeitfenster der Exposition.

PDFree beseitigt dieses Risiko vollständig. Weil kein Server beteiligt ist:

  • Kein DSGVO-Risiko — es werden keine personenbezogenen Daten an einen externen Verantwortlichen außerhalb deines Geräts gesendet
  • Keine Datenspeicherung — es gibt nichts zu speichern; Dateien existieren nur während der Verarbeitung im Arbeitsspeicher deines Browsers
  • Kein Datenleck-Risiko — ein Server kann kompromittiert werden; auf deinen Browser-Arbeitsspeicher kann niemand aus der Ferne zugreifen
  • Sicher für vertrauliche Dokumente — Verträge, medizinische Unterlagen, Finanzdokumente und juristische Akten lassen sich alle sicher verarbeiten
  • Funktioniert in air-gapped Netzwerken — während der PDF-Verarbeitung werden keine ausgehenden Verbindungen aufgebaut

Häufig gestellte Fragen

Kann ich diese PDF-Tools ohne Internetverbindung nutzen?

Ja. Nach deinem ersten Besuch funktioniert PDFree vollständig offline. Ein Service Worker speichert die gesamte Anwendung zwischen — Skripte, WebAssembly-Module und Schriftarten. Bei jedem späteren Besuch, selbst ohne Internet, laden alle Tools aus dem Cache und verarbeiten PDFs ohne Netzwerkverbindung.

Wird meine PDF-Datei bei PDFree tatsächlich hochgeladen?

Nein. Deine PDF wird über die File API des Browsers von deiner lokalen Festplatte gelesen und im Arbeitsspeicher des Browsers verarbeitet. Kein Byte deiner Datei wird über eine Netzwerkverbindung gesendet. Du kannst das selbst überprüfen: Öffne die DevTools deines Browsers → Tab „Netzwerk“ und beobachte, ob irgendwelche Datei-Upload-Anfragen auftauchen — es gibt keine.

Wie unterscheidet sich das von cloudbasierten PDF-Tools?

Cloudbasierte Tools laden deine Datei auf ihre Server hoch, verarbeiten sie remote und senden dir das Ergebnis zurück. Dein Dokument befindet sich währenddessen vorübergehend auf fremder Infrastruktur. PDFree ist das Gegenteil — die Verarbeitungs-Engine läuft in deinem Browser. Deine Datei verlässt dein Gerät nie. Das macht PDFree grundsätzlich sicherer für sensible Dokumente und nutzbar ohne Internet nach dem ersten Laden.

Funktioniert PDFree auf dem Handy ohne Upload?

Ja. PDFree funktioniert in iOS Safari, Android Chrome und allen modernen mobilen Browsern. Die WebAssembly-basierte Verarbeitung funktioniert auf Mobilgeräten genauso — kein Upload, kein Server. Du kannst PDFree auch über das Menü deines Browsers als PWA installieren, für schnellen Offline-Zugriff vom Startbildschirm aus.

Ist es wirklich kostenlos, ohne versteckten Haken?

Ja. PDFree hat keinen kostenpflichtigen Plan, keine Tageslimits, keine Dateigrößenbeschränkung, keine Wasserzeichen im Ergebnis und keine Kontopflicht. Alle Tools sind für immer kostenlos. Das Projekt ist Open Source unter der GNU AGPLv3 — du kannst den Quellcode einsehen, um genau zu prüfen, wie es funktioniert.

Keine Registrierung. Kein Download. Läuft sofort in deinem Browser — und offline nach dem ersten Besuch.
